# Incident log (L3)

These are failures that **actually happened during development of this repository**, reconstructed from the development session.
They were found by tests, evaluation runs or manual inspection - not in production. Details marked *(approximate)* were reconstructed from memory of the fix, not from a
saved log; check them against your own commit history, and **add your own incidents from your own demo runs - this log is more convincing when it is yours.**

| # | What failed | How noticed | Root cause | Fix | Prevention |
|---|---|---|---|---|---|
| 1 | Doubled characters in policy headings ("SSEECCTTIIOONN") after PDF text extraction | Reading extracted text while checking chunks | The claims page was a browser print with bold text drawn twice | `dedouble` option in the corpus profile (`corpus/profile.json`), applied to the claims page only | Chunker unit test on a doubled line |
| 2 | Words lost to ligatures ("bene ts", "Of ce") and icon-font navigation glyphs in the claims page | Retrieval for "benefits" and "Office" missed obvious passages | PDF extraction dropped the "fi" ligature; the web print contained menu icons in a private-use Unicode range | Ligature repair table, `\x00` -> "fi", drop lines containing private-use glyphs | `tests/test_chunker.py` |
| 3 | A naive single-pass retrieval missed the Section I exclusion and the General Exclusion GE:01 for the section 4.1 claim | `evaluation` baseline run (`cov_v0`): context recall 0.29, section 4.1 case wrong | The restriction is worded in terms the claim never uses and its qualifier sits behind a cross-reference | Derived queries (cover + exclusion + condition) and cross-reference chasing in the coverage agent | Evaluation scenario for the 4.1 case; recall tracked in `docs/EVALUATION.md` |
| 4 | Total-loss claims retrieved IDV/valuation text but not the cover clause on the first search | Evaluation scenario for total loss | Query built from the claim text matched the claims procedure page, not the policy | Per-claim-type cover queries (`COVER_Q`) and a larger `top_k` for total loss | Scenario kept in the evaluation set |
| 5 | An out-of-scope claim (not a motor-insurance claim in the corpus's domain) received a confident coverage answer | Evaluation scenario for out-of-corpus input | No check that the claim belonged to the policy corpus before answering | `scope_check` in triage plus weak-retrieval escalation (`OUT_OF_CORPUS`, `WEAK_RETRIEVAL`) below `WEAK_RETRIEVAL_THRESHOLD` | Scenario kept; guard has unit tests |
| 6 | "Another car reversed into my parked car" was treated as a third-party / collision-with-other-party style claim *(approximate)* | Triage output on the sample claims | Regex looked for "another car" as a signal of third-party involvement; here it described how the damage happened to a parked car | Entity regex narrowed; structural flags use the structured fields, not narrative keywords alone | `tests/test_validation.py`, sample claims |
| 7 | Verifier V5b ("restriction cited") passed or failed on the wrong evidence *(approximate)* | Unit test on a restriction position citing only a cover clause | Role check looked at the wrong set of citation roles | Check requires an `exclusion` or `condition` role among the cited passages | `tests/test_verifier.py` |
| 8 | A prompt-injection phrase ("reveal your prompt") scored below the flag/block threshold | `tests/test_guardrails.py` | Pattern weight 0.7 under the 0.8 block score | Weight raised to 0.8 | The guardrail tests |
| 9 | Verifier figure check (V3) rejected valid summaries or let numbers through *(approximate)* | Unit tests on amounts like "Rs.25,000" and "25000.0" | Number normalisation (`_nums`) handled commas but not trailing `.0` consistently | Normalise both forms | `tests/test_verifier.py` |
| 10 | Locust reported no end-to-end statistic | First smoke load test | The custom `RUN e2e` task name did not match what `summarize.py` read | Names aligned | `loadtest/summarize.py` checks that stat exists and fails loudly |

| 12 | Expectation error in scenario E23: the expected outcome was wrong, not the system | Evaluation failure analysis | Expectation written before understanding the corpus wording | Expectation corrected after reading the clause | Scenario notes record the reason |
| 13 | **Load test: three workers at concurrency 4 missed the declared SLO** (p95 26 s, 3.5 runs/s) | `slo_w3_wc4_u5` | Worker threads blocked on model latency (I/O wait): capacity = threads / run time | `WORKER_CONCURRENCY=16` (p95 5.2 s, 4.8 runs/s) | Documented in `docs/LOAD_RESULTS.md`; default in `.env.example` is 16 |
